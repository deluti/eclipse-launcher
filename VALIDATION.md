## Установка Fabric / Quilt и игровые профили

Добавлен установщик по кнопке «+» рядом с выбором версии. Он получает версии Fabric / Quilt из официальных Meta API, выбирает стабильный выпуск первым, наследует план обычного Minecraft и добавляет библиотеки и точку запуска загрузчика. Java, ресурсы, базовый клиент и natives переиспользуются. Переопределяемые Maven-артефакты заменяются в classpath по группе и имени, чтобы не загружать одновременно разные версии одной библиотеки. Библиотеки проверяются по размеру и SHA-1 из профиля или Maven sidecar; неподтверждённые/посторонние источники не принимаются.

Профили сохраняются между запусками, а выбор профиля сохраняется сразу. Игровые папки модифицированных профилей изолированы в `data/instances/<id>`; vanilla использует `data/game`. JVM и ресурсы остаются общими. Смена профиля переключает файловое дерево и галерею; несохранённый файл защищён прежним диалогом. «Файлы → Моды» открывает каталог активного профиля.

Fabric дополнительно обнаружил тестовый `eclipse_probe 1.0.0`. Проверки использовали отдельные игровые папки `.test-data/fabric-launch/game` и `.test-data/quilt-launch/game`; после проверки процессы остановлены. ## Позы, idle, центрирование и иконка

В главном меню персонаж и платформа центрированы относительно сцены и кнопки игры. При создании сцены случайно выбирается одна из двух поз: рука у головы или расслабленный наклон. Введены суставы плеч, локтей, бёдер, коленей, головы и плаща; текстуры сегментов сохраняют вертикальную развёртку скина. Сэмплирование дыхания и покачивания не пересоздаёт геометрию и текстуры. Нижняя точка стоп корректируется к уровню платформы. Idle обновляет геометрию до 60 Гц, камера при перетаскивании — до 120 Гц; используется общий цикл навигации, по одному ожидающему кадру, без очереди сверх него. При скрытии сцены и сворачивании фаза анимации останавливается.

Два теста проверяют положение поднятой/опущенной руки, непрерывность суставов локтя и колена, отсутствие скачков и контакт стоп с платформой в обеих позах и узких руках. UI-проверка по очереди включает обе позы и проверяет рост фазы и числа кадров модели; отдельно проверяется остановка idle при сворачивании. Снимки: `.test-data/ui-previews/pose-handathead.png`, `pose-relaxed.png`. После центрирования: 119,8 FPS интерфейса, 120,1 новых положений/с при вращении.

В EXE встроена иконка зелёного пиксельного затмения в размерах 16, 32, 48, 64, 128 и 256 px. Тот же ресурс назначен окну. Нативная иконка извлечена через Windows `ExtractAssociatedIcon` из собранного EXE и просмотрена: `.test-data/exe-icon.png`.

## Запуск по никнейму

Добавлен отдельный режим «По никнейму», включённый по умолчанию с ником `Player`. В настройках находятся поле ника и выбор «По никнейму / Microsoft», оба сохраняются в `settings.json`. Допустимы 3–16 символов `A–Z`, `a–z`, `0–9`, `_`; пробелы по краям убираются. Локальный UUID совместим с Java UUID v3 для `OfflinePlayer:<имя>`; проверен известный вектор `Notch`.

Локальный запуск использует отдельный `OfflineAccount` и отдельный вход в процедуру запуска, с `userType=legacy` и без токена аккаунта. Для него лаунчер не выполняет OAuth, Xbox/XSTS, проверку лицензии и не читает сохранённую Microsoft-сессию. Режим Microsoft по-прежнему использует только `LicensedAccount` с проверкой лицензии; ошибки входа не включают локальный режим автоматически. Поле ника отключается при выборе Microsoft, где имя берётся из аккаунта.

Реальный Minecraft 26.3 запущен как `Eclipse_Test`: создано окно SDL, инициализирован графический адаптер и загружен GUI-атлас. Игровая папка проверки изолирована в `.test-data/offline-launch/game`, ранее установленные файлы Java/библиотек/ресурсов переиспользованы. После загрузки GUI тестовый процесс остановлен проверкой; его код остановки не является проверкой штатного выхода игры. Результат и лог: `.test-data/offline-launch/result.json`, `java.log`. Мир не создавался. Подключение к серверам и Realms не проверялось.

Три новых теста проверяют стабильный UUID, валидацию ника и сборку локальных аргументов без HTTP и demo-флага. UI-проверки подтверждают сохранение ника, обновление имени в хедере, открытие настроек нажатием на ник, ввод A/D в поле ника, переключение двух способов входа и отсутствие наложений на 1040×720 и 1280×850.

## Звуки интерфейса

Добавлены шесть оригинальных синтезированных сигналов PCM 44,1 кГц, mono, 16 bit, длительностью 18–80 мс: нажатие, выбор, подтверждение, возврат, регулировка/ввод и ошибка. Кнопки, включая диалоги и управление окном, озвучиваются централизованно в `PixelButton.OnClick`; отдельно подключены вкладки A/D/Enter, выпадающие списки, галерея, скины/плащи, дерево файлов, текстовый ввод, ползунок и камера. Программная привязка данных и кадры вращения не создают щелчков.

Синтез и воспроизведение выполняются в отдельном потоке, который спит без событий. WAV-буферы закреплены в памяти до остановки native playback. Частые повторы ограничены интервалом 42–60 мс; хранится только последнее действие, очередь звуков не растёт. Нет обращений к файлам и сети во время действий. Проверка `--audio-check` подтвердила успешный приём всех шести сигналов реальным Windows `PlaySound`.

Два теста проверяют формат WAV, длины, тихую амплитуду, нулевые начало и конец, сохранение настройки звука и совместимость старых настроек. UI-проверка контролирует одиночный щелчок кнопки, отсутствие звука у отключённых/заглушённых контролов, отдельные сигналы выбора и подтверждения вкладки, тихую программную установку ползунка и его озвученную регулировку клавиатурой. Выключатель помещается без пересечений на 1040×720 и 1280×850. Последний замер вращения — 120,1 новых положений/с, хедера — 120,1 FPS; в неподвижном меню — 119,8 FPS.

## Просадка при вращении

Просадка воспроизведена отдельным замером непрерывного перетаскивания: 19,8 новых положений персонажа в секунду, столько же кадров хедера, около 84,7 МиБ/с выделений памяти в UI-потоке. Прежний замер неподвижного меню эту проблему не обнаруживал.

Платформа теперь строится один раз как текстура и рисуется одним преобразованием вместо сотен отдельных полигонов. Освещение текстур граней рассчитывается при смене скина. Буферы изображения персонажа и контура используются повторно; контур обрабатывает только область персонажа. Сортировка граней, проекции и смещения контура также используют готовые массивы. В главном меню движения мыши изменяют камеру, а сцена и частицы обновляются одним общим кадром с ограничением 120 Гц. При перерисовке учитываются прежние и новые границы модели.

После исправления: около 120 FPS при обычной непрерывной подаче движений, 116,7 FPS при восьми событиях мыши на кадр (примерно 960 событий/с). Выделения памяти в стресс-проверке — около 0,3 МиБ/с. Измеряется число новых отрисованных положений, а не только обновления неподвижного изображения. UI-проверка требует не менее 105 новых положений/с и ограничивает выделения 8 МиБ/с; до исправления она падала. Результаты сохраняются в `.test-data/ui-previews/rotation.json`. Пять вкладок, два размера окна, вращение, масштаб, контур и отсутствие наложений проверены.

## Зелёная палитра, контур и фон

Свечение и частицы используют приглушённый зелёный оттенок `#476F2D` с двумя близкими оттенками частиц. Слои эффекта остаются за тёмным хедером и карточками. Эллиптическое свечение у ног удалено; пиксельная платформа сохранена. Контур строится из альфа-силуэта самого персонажа и плаща, ширина 2–5 px зависит от масштаба; платформа в маску не входит. Готовый персонаж с контуром кэшируется до изменения камеры, внешнего вида или размера сцены.

Общий кэшированный фон содержит статичный пиксельный шум: отклонение от базового цвета ±2 уровня RGB, зерно 3×3 px, без повторяющихся фигур. Сохранено пиксельное затемнение от нижнего края окна до верхней границы кнопки «Играть». Координаты фона общие для сцены, панели запуска и нижней строки, чтобы между ними не появлялось швов. Внешний вид проверен на снимках `.test-data/ui-previews/eclipse.png` и `compact.png`; прежние проверки вращения, масштаба, вкладок и кнопок проходят.

## Анимация и расположение эффекта

Целевая частота навигации — 120 кадров/с. Используется высокоточный ожидаемый таймер Windows без активного ожидания; статический фон и карточки кэшируются. После завершения перехода обновляется только область частиц; изображение персонажа кэшируется и пересоздаётся по вводу, смене внешнего вида и размера окна. При сворачивании и скрытии окна цикл останавливается.

Эффект находится за хедером по порядку отрисовки: сначала свечение и частицы, затем непрозрачные пиксели тёмного хедера и карточки. Пиксельный край хедера маскирует верх эффекта, свечение имеет плавный спад без горизонтальной отсечки. Поле частиц продолжается с локальной координаты Y=96 до Y=260, в том числе в верх сцены, примерно до головы Steve. Общее место навигации остаётся 176 px, содержимое вкладок не сдвигается. Скорость падения 30–42 px/с с небольшим ускорением; время жизни 3–4,2 с, с постепенным затуханием. UI-проверка реального изображения проверяет, что сплошная часть хедера остаётся тёмной, а частицы видны ниже навигации. Автоматические проверки ограничивают число частиц 128, проверяют область рисования, достижение области сцены и исчезновение после прекращения эмиссии.

После оптимизации вращения и замены узора шумом: 119,9 фактических перерисовки/с в неподвижном меню; процессорное время процесса около 248 мс/с на этом компьютере. Замер сохраняется в `.test-data/ui-previews/animation.json`; проверяются остановка при сворачивании и возобновление при восстановлении. Все пять вкладок в двух размерах окна и регрессия наложения надписей также проходят UI-проверки.

Опубликованные DLL и EXE совпадают по SHA-256 с проверенной сборкой; smoke-запуск собранного EXE завершился успешно, первая отрисовка — 328,2 мс. В smoke-режиме аудиопоток не запускается.

## Наложение надписей на кнопках

Причина воспроизведена отдельным графическим регрессионным тестом до исправления: `ButtonBase` использует стиль `Opaque`, а `PixelButton.OnPaint` не очищал фон при `Quiet=true`. Повторно используемый буфер сохранял фрагменты прежней кнопки «Обновить» и накладывал на них «Отмена». Нижние два ряда пикселей обычных кнопок также не заполнялись.

`PixelButton` теперь очищает фон в начале каждого кадра, до рисования рамки и текста. Тест проверяет совпадение чистого кадра с кадром на ранее использованном буфере, смену надписей, наведение и уход мыши, обычное и отключённое состояния и полное заполнение кнопки до нижнего края. Он падал до изменения и проходит после него.

На всех пяти вкладках в окнах 1040×720 и 1280×850 дополнительно запускается локальная ожидающая операция без HTTP: проверяются показ и нажатие «Отмены», её скрытие после отмены, отсутствие пересечения с текстом статуса и отсутствие пересечений кнопок аккаунта/управления окном. Снимки этих состояний: `.test-data/ui-previews/busy-*.png`.

До входа используется оригинальный Steve 64×64 из установленного официального Minecraft 26.3. Текстура встроена в EXE; её SHA-256 проверяется UI-тестом, запросов в сеть для неё нет.

Карточки теперь выравниваются по верхней грани. Выбранная находится в центре, соседние частично заходят под более близкие по Z. Ширина постоянная, базовая высота дальней карточки 100 px, ближайшей 108 px, выбранной 116 px: выступ уменьшен с прежних 58 до 16 px. Общая высота навигации уменьшена до 176 px. Тесты редактора проверяют кодировку/BOM, отказ редактировать бинарные и внешние файлы и защиту от перезаписи внешних изменений.

**Вход Microsoft и изменение скина/плаща реального аккаунта пока заблокированы допуском приложения к Minecraft API.** Это не мешает отдельному запуску по никнейму, проверенному выше. Microsoft OAuth refresh, Xbox Live и XSTS ранее проверены с реальной сохранённой сессией пользователя, все три этапа возвращали HTTP 200. Заполненный пользователем Client ID сохранён. В обычных автоматических тестах ответы сервисов имитируются. UI-тест использует изолированную конфигурацию без Client ID. Тестовые скриншоты галереи существуют только в отдельной тестовой папке.

Измерение подготовки файлов не включает задержку проверки лицензии и загрузку клиента Java/Minecraft. Данные для входа официального лаунчера не читались и не импортировались.

## Исправление входа Microsoft

При первоначальной анонимной проверке Microsoft возвращал `invalid_request: redirect_uri is not valid`. Отдельная проверка поддержки public client возвращала `AADSTS70002` — приложение не настроено как mobile/desktop. Пользователь подтвердил доступ к регистрации и сохранил desktop-платформу с `http://localhost` и разрешением public client flows.

После сохранения `--check-login` для того же Client ID проходит на реальном сервере Microsoft: прежняя ошибка `redirect_uri` не воспроизводится. Проверка не открывала интерактивный вход и не получала пользовательские токены. В лаунчер добавлено предварительное обнаружение ошибки регистрации и читаемая инструкция в собственном окне.

## Исправление HTTP 400 Xbox Live

Причина воспроизведена регрессионным тестом до исправления: стандартная web-сериализация `JsonContent.Create` преобразовывала чувствительные к регистру поля Xbox в camelCase. Применены явные `JsonSerializerOptions.Default`, сохраняющие имена полей. Усилен тест полной цепочки: он проверяет фактический JSON и заголовок Xbox, а не только выдаёт заготовленный успешный ответ.

Реальная проверка с одной и той же сохранённой сессией:

- Обновление Microsoft OAuth: HTTP 200.
- Контрольный запрос Xbox со старым camelCase: HTTP 400.
- Исправленный запрос Xbox: HTTP 200.
- XSTS: HTTP 200.
- Minecraft `authentication/login_with_xbox`: HTTP 403, серверное сообщение `Invalid app registration`.
- Проверен актуальный `launcher/login` с `xtoken` и `platform=PC_LAUNCHER`: также HTTP 403. Смена endpoint не снимает ограничение приложения.

В постоянной диагностике оставлены только штатные запросы: контрольный старый формат и запрос альтернативного endpoint использовались для расследования и удалены из инструмента. Токены и тело ответов не печатались. Частичная сессия сохраняется под DPAPI. Для Minecraft нужен внешний допуск Client ID; описание обращения подготовлено в `MINECRAFT-API-REQUEST.md`.
